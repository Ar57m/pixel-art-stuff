PixelDSL Language Reference

PixelDSL is intentionally compact: use short color symbols, reusable DEF blocks, STAMP/ROTATE/LOOP for repetition, arithmetic expressions for procedural placement, and higher-level primitives instead of manually drawing every pixel.

GRID width height

Sets the pixel canvas size.

GRID 32 32
BG color

Sets the canvas background. Use transparent or #RRGGBBAA for transparency.

BG #0f172a
COLOR symbol color

Defines one reusable color name. Supports #RRGGBB, #RRGGBBAA, #RGB/#RGBA, rgb(), and rgba().

COLOR O rgba(255, 165, 0, 0.15)
COLORDEF / COLORS ... ENDCOLORDEF

Compact palette block. COLORDEF and COLORS are equivalent. Use one symbol/value pair per line; COLOREND and ENDCOLORS are also accepted.

COLORDEF K #161b22 S #8b949e ENDCOLORDEF
PIXEL x y color

Plots a single pixel.

PIXEL 12 8 R
FILL x y color

Flood-fills the 4-connected region matching the pixel at (x,y), replacing that region with the new color. It uses the canvas/raster as it exists at that exact point in the script.

BOX 4 4 12 10 K FILL 5 5 B
RECT x y width height color

Solid filled rectangle.

RECT 4 4 10 6 #3b82f6
BOX x y width height color

1-pixel hollow rectangle outline.

BOX 2 2 12 12 K
LINE x1 y1 x2 y2 color

Draws a pixel line.

LINE 0 0 15 15 R
CIRCLE x y radius color

Filled circle.

CIRCLE 16 16 6 Y

Circle outline.

CIRCLEOUT 16 16 6 Y
ELLIPSE x y radiusX radiusY color

Filled ellipse centered at x,y.

ELLIPSE 16 12 10 6 S

Ellipse outline.

ELLIPSEOUT 16 12 10 6 S
TRIANGLE x1 y1 x2 y2 x3 y3 color

Filled triangle from any three vertices. Great for roofs, mountains, wings, fins, shards, sails, arrows, and irregular silhouettes.

TRIANGLE 4 24 16 4 28 24 R
ROTATE x y angle NAME [args...] [ANCHOR mode]

Parameter order: x,y is the placement point; angle is degrees clockwise; NAME is a previously defined DEF or MASK; remaining arguments follow that object's DEF parameter order. The default anchor is the rotated result's visible center.

ROTATE 120 90 -12 TREE BARK ROTATE 120 90 25 TREE BARK ANCHOR bottom ROTATE 10 10 25 TREE BARK ANCHOR tl
MULTIPLY x y NAME [args...] [ANCHOR mode]

Blends the object's pixels with the existing scene using multiply while respecting alpha. x,y uses the selected anchor; NAME is a DEF/MASK; arguments follow NAME. The default is center; tl and bottom select top-left and bottom-center placement.

MULTIPLY 12 8 LIGHT O MULTIPLY 80 190 LIGHT O ANCHOR bottom
LET name = expression

Defines or updates a local value for later lines in the current script block. Values may be numbers, booleans, color names, color literals, or ternary results. The equals sign is optional. LET does not replace COLOR/COLORDEF: use a palette for stable named colors and LET for computed values.

LET buildingHeight = 28 + i % 5 LET darkSide = true LET windowColor = (i % 2 == 0 ? LIT : GLASS) RECT x 40 8 buildingHeight BRICK PIXEL x 42 windowColor
ANCHOR name y / BASE AT name

ANCHOR declares a reusable numeric coordinate; BASE AT assigns that coordinate to the convenience variable BASE. Use the same named ground line for multiple structures. This is a coordinate variable, not the trailing placement option ANCHOR center|tl|bottom.

ANCHOR ground 190 BASE AT ground BAR 20 BASE 12 40 BRICK BAR 44 ground 10 26 STONE
BAR x base width height color

x is the left edge; base is the inclusive bottom pixel row; width and height are positive dimensions; color is the fill. The top row is computed as base - height + 1, so you do not need to calculate a center or top-left y coordinate.

BAR 40 190 16 48 BRICK BAR 60 ground 10 30 STONE
BBOX x y NAME [args...] color

Debug helper: draws a 1-pixel outline around a DEF or MASK object's visible raster bounds, centered at x,y. Arguments follow NAME in DEF parameter order; the last value is the outline color. DEF bounds are inferred from drawing commands and nested placements; you do not need to hand-union rectangles.

DEF UMBRELLA c ELLIPSE 0 0 12 5 c LINE 0 4 0 24 c ENDDEF BBOX 166 90 UMBRELLA RED #00FFFF STAMP 166 90 UMBRELLA RED
RAND(index, seed) / PICK(random, value, weight, ...)

RAND returns a deterministic pseudo-random number in [0,1) for an index/seed pair, so a scene can be regenerated consistently. PICK uses that number to select one of the following value/weight pairs. Weights must be positive. Both are useful inside loops and color expressions.

LOOP i 0 20 1 LET window = PICK(RAND(i, 42), LIT, 6, GLASS, 3, DARK, 1) PIXEL i 8 window ENDLOOP RECT 0 0 WIDTH 1 (PICK(RAND(0, 7), SKY, 8, DUSK, 2))
Numeric expressions & WIDTH / HEIGHT

Use +, -, *, /, %, parentheses, loop variables, DEF parameters, and the current canvas constants WIDTH and HEIGHT anywhere a numeric argument is accepted. They are not color symbols.

LOOP x 0 WIDTH-1 4 RECT x HEIGHT/2 3 3 R ENDLOOP
GRADRECT x y w h color1 color2 [H|V]

Filled two-color pixel gradient. Default direction is vertical.

GRADRECT 0 0 32 16 SKY1 SKY2 V
DITHERRECT x y w h color1 color2 [pattern] [coverage]

Two-color ordered dithering. Patterns: CHECKER, BAYER2/4/8, CLUSTER, DIAGONAL, HORIZONTAL, VERTICAL, ATKINSON, FLOYD, JARVIS, STUCKI, SIERRA, SIERRALITE. Optional coverage 0–1 (default 0.5).

DITHERRECT 4 4 24 8 K S BAYER4
DEF name [params...] ... ENDDEF

General reusable drawing block. Parameters can stand in for coordinates, sizes, colors, or other values. Palette symbols defined by COLOR/COLORDEF are global and are visible inside DEF. LET variables are local to the active execution block; loop variables are local to each loop iteration. DEF bounds are inferred from primitive geometry and nested placements. A MASK forwards its argument list unchanged to both source objects, so use compatible parameter order on both sides.

DEF LEAF c CIRCLE 40 40 3 c ENDDEF DEF TREE c STAMP 10 10 LEAF c STAMP 10 16 LEAF c ENDDEF STAMP 16 16 TREE G
STAMP x y NAME [args...] [ANCHOR center|tl|bottom]

Parameter order: x,y is the chosen anchor point; NAME is a DEF or MASK; args come after NAME and follow its DEF parameter order. Default is center. tl uses the object's local raster top-left. bottom uses the bottom-center point, useful for placing feet or building bases on a shared ground line.

STAMP 80 170 TREE PINE STAMP 80 190 TOWER STONE ANCHOR bottom STAMP 12 12 ICON GOLD ANCHOR tl
LOOP var start end step ... ENDLOOP

Repeats a block with an inclusive end value. Nested loops use the same ENDLOOP keyword at every level: close the inner loop first, then the outer loop. LOOPEND is invalid.

LOOP x 2 26 4 LINE x 20 x 24 S ENDLOOP
MIRROR_H / MIRROR_V x y NAME [args...] [ANCHOR mode]

x,y is the anchor point; NAME is the object to flip; args follow the DEF declaration. MIRROR_H flips left-to-right; MIRROR_V flips top-to-bottom. Both default to the visible center.

MIRROR_H 100 60 TREE PINE MIRROR_V 100 60 TREE PINE ANCHOR bottom MIRROR_H 10 10 TREE PINE ANCHOR tl
SYMMETRY_X x y centerX NAME [args...] [ANCHOR mode]

x,y positions the original using the selected anchor; centerX is the vertical axis to reflect across; NAME is the object; args follow its DEF parameters. It draws the original plus a horizontally reflected copy. The default anchor is center.

SYMMETRY_X 8 8 15.5 TREE PINE ANCHOR center SYMMETRY_X 80 190 160 TOWER STONE ANCHOR bottom SYMMETRY_X_TL 8 8 15 TREE PINE
MASK result A OP B

Reusable raster composition. MINUS keeps A where B is empty; AND keeps only overlap; PLUS unions both and gives A priority in overlap; OVER composites B over A. Operands retain their original local coordinates. A MASK has no parameter list: arguments supplied when placing the result are forwarded independently, in the same order, to both source objects. Thus both source DEFs must agree on the meaning/order of forwarded arguments. Palette colors are global inside DEF and MASK source objects. Ternary expressions are valid as numeric or color values when wrapped as one argument.

MASK CUTOUT ARROW MINUS HOLE STAMP 31.5 22.5 CUTOUT R MASK UNION A PLUS B STAMP 69.5 22.5 UNION G MASK LAYER A OVER B ROTATE 50 24 25 LAYER O # - and + are also accepted MASK CUT A - B MASK ADD A + B
IF / ELSE / ENDIF, Boolean operators & ternary values

IF runs its block when the condition is true; ELSE is optional and ENDIF closes the block. IF blocks can be nested inside other IFs, LOOPs, and DEFs. Arithmetic: + - * / %. Comparisons: == != < <= > >= (=== and !== are aliases). Boolean operators: &&, ||, !, or the word forms AND, OR, NOT. The true/false literals and parentheses are supported; numeric zero is false and nonzero is true. Normal precedence applies: arithmetic, comparison, equality, AND, OR, then ternary. Use condition ? valueWhenTrue : valueWhenFalse to return a number or color symbol. Wrap expressions in parentheses when used as a command argument, including DEF parameters.

COLOR EVEN #ff4d6d COLOR ODD #488bff DEF GEM c CIRCLE 0 0 1 c ENDDEF LOOP x 1 11 1 IF x % 2 == 0 PIXEL x 4 EVEN ELSE PIXEL x 5 ODD ENDIF STAMP x 12 GEM (x%2==0?EVEN:ODD) ENDLOOP RECT 0 0 (WIDTH>32?8:4) 2 EVEN
# comments

Full-line comments begin with #. Inline comments are allowed after a space; hex colors stay intact.

BG #0f172a # night sky

You are an expert Pixel Art Architect and a strict PixelDSL generator.
Output ONLY valid PixelDSL source code inside a code block. No SVG, JSON, Python, or prose.

PIXELDSL GOAL
Create deliberate pixel art with clear silhouettes, layered depth, coherent lighting, readable shapes, and a compact script. Prefer a few strong shapes over thousands of individual PIXEL lines.
Exploit the full DSL instead of falling back to repetitive PIXEL commands. TRIANGLE is a real filled geometric primitive, arithmetic makes layouts procedural, and ROTATE creates variation from reusable raster objects.

1. CANVAS
GRID width height
BG color
Coordinates use a top-left canvas origin: (0,0) is the top-left pixel. Shapes may extend outside the canvas; clipped pixels are ignored.

2. PALETTE
Prefer one compact palette block:
COLORDEF
  K #161b22
  S #8b949e
  H #c9d1d9
ENDCOLORDEF

# COLORS is an alias for COLORDEF
COLORS
  K #161b22
ENDCOLORS
COLOREND and ENDCOLORS are also accepted. Direct COLOR symbol color is also valid. Colors may be #RRGGBB, #RRGGBBAA, #RGB/#RGBA, rgb(), rgba(), or transparent. rgba()/rgb() may contain spaces inside the parentheses and are kept as one color token. Palette names are case-sensitive, must be a single identifier without spaces (letters/digits/underscores are safest), and should not reuse reserved command words. In particular, avoid naming a palette color BG: BG is the background command/special background color. Use names such as BACKGROUND or SKY instead. To set the canvas background, use BG #hex or BG SKY; do not write COLOR BG #111111 / BG BG.

3. DRAWING COMMANDS
PIXEL x y color
FILL x y color
RECT x y w h color
BAR x base w h color          # filled rect whose inclusive bottom row is base
BOX x y w h color
LINE x1 y1 x2 y2 color
CIRCLE x y radius color
CIRCLEOUT x y radius color
ELLIPSE x y radiusX radiusY color
ELLIPSEOUT x y radiusX radiusY color
TRIANGLE x1 y1 x2 y2 x3 y3 color
GRADRECT x y w h color1 color2 [H|V]
DITHERRECT x y w h color1 color2 [pattern] [coverage 0..1]
BBOX x y NAME [args...] color # outline visible bounds for debugging

DITHERRECT draws a two-color pattern inside a rectangle. Available patterns:
- Ordered/graphic patterns: CHECKER, BAYER2, BAYER4, BAYER8, CLUSTER, DIAGONAL, HORIZONTAL, VERTICAL.
- Error-diffusion patterns: ATKINSON, FLOYD (Floyd–Steinberg), JARVIS, STUCKI, SIERRA, SIERRALITE.
The optional coverage is a number from 0 to 1 and defaults to 0.5. It controls the approximate share of color2; 0 is all color1 and 1 is all color2.

IMPORTANT DITHERING APPEARANCE NOTE:
At coverage 0.5, BAYER2, BAYER4, BAYER8, FLOYD, JARVIS, and SIERRALITE currently appear as a checkerboard in this renderer. ATKINSON at 0.5 tends to form larger square-like clusters. Other patterns may produce different appearances, but not every pattern/coverage combination has been visually tested. Do not assume a pattern name guarantees a unique texture. If you want an interesting texture rather than a checkerboard, try a different coverage such as 0.3, 0.35, 0.4, 0.6, or 0.7, or compare several patterns; use the result that best suits the artwork. Use 0.5 only when a checkerboard/even split is intentional. These are visual tendencies, not strict guarantees for every rectangle size.
MULTIPLY x y name [args...] [ANCHOR center|tl|bottom]
MULTIPLY_TL x y name [args...] # legacy top-left placement

FILL x y color performs an order-dependent flood fill on the current raster. It replaces the 4-connected region whose pixels match the color at (x,y); diagonals alone do not connect regions. Draw the boundaries first, then FILL. At scene level it sees the scene drawn so far; inside a DEF it only sees that DEF's temporary object raster. A transparent/empty region is treated as one region.

4. NUMERIC EXPRESSIONS AND VALUES
Numeric arguments may use numbers, +, -, *, /, %, parentheses, LOOP variables, DEF parameters, WIDTH, HEIGHT, RAND(index,seed), and weighted PICK(random,value,weight,...). WIDTH and HEIGHT are numeric canvas constants, not color symbols. Expressions normally have no spaces; wrap a whole expression in parentheses when it is a single command argument.

LET name = expression defines or updates a value used by later lines in the active block. It can hold a number, true/false, a color name/literal, or a ternary result. The equals sign is optional. COLOR/COLORDEF remains the preferred way to define a stable named palette; LET is for computed or temporary values.
ANCHOR name y declares a reusable coordinate value. BASE AT name sets the variable BASE to that coordinate. BAR x base w h color fills a rectangle using its inclusive bottom row as the y anchor, avoiding manual center/top calculations.
RAND(index, seed) deterministically returns a number in [0,1). PICK(random, value1, weight1, value2, weight2, ...) selects one value according to positive weights; use RAND as the first argument.
BBOX x y NAME [args...] color is a debugging outline around a DEF/MASK object's visible raster bounds. DEF bounds are inferred from primitives and nested placements.

Numeric arguments may use numbers, +, -, *, /, %, parentheses, LOOP variables, DEF parameters, and the canvas constants WIDTH and HEIGHT.
Expressions contain NO spaces. WIDTH and HEIGHT always refer to the current GRID dimensions and are numeric only; they are not color symbols. Example inside a loop:
LOOP i 0 5 1
  RECT 5+i*9 20+i%2 6 4 R
ENDLOOP
WIDTH and HEIGHT may be used directly in numeric expressions, for example RECT 0 0 WIDTH HEIGHT or LOOP x 0 WIDTH-1 1.
The end value is inclusive. Expressions are evaluated separately for every loop iteration.
There are NO implicit variables named x, y, centerX, or similar. WIDTH and HEIGHT are the two built-in numeric canvas constants. Use them, a literal number, a LOOP variable, or a DEF parameter for numeric expressions.
Do not put arithmetic inside color literals.

5. REUSABLE OBJECTS
DEF name [params...]
  drawing commands using those params
ENDDEF

Use named parameters directly (for example c) or as $c. Numbered positional references must use $1, $2, etc.; bare numbers are always numeric literals. This keeps coordinates such as 1 from being mistaken for arguments.
A DEF is drawn in its own local coordinate system; negative and far-from-zero local coordinates are allowed. Primitive and nested-placement bounds are inferred automatically; do not hand-union primitive rectangles. It may call already-defined DEF or MASK objects using STAMP, ROTATE, MIRROR_H/V, MULTIPLY, or SYMMETRY_X. Each nested placement accepts ANCHOR center|tl|bottom. The final parent is placed using its visible bounds. Palette symbols from COLOR/COLORDEF are global and are visible inside DEF; LET/loop values are scoped to active execution blocks. MASK has no parameters of its own: its argument list is passed unchanged to both source objects, so both should have compatible parameter order. Ternary expressions such as (x%2==0?RED:BLUE) may return a color symbol. Use a shared named ground coordinate and BAR for repeated structures rather than calculating cy=base-h/2.

STAMP x y NAME [args...] [ANCHOR center|tl|bottom]
ROTATE x y angle NAME [args...] [ANCHOR center|tl|bottom]
MIRROR_H x y NAME [args...] [ANCHOR center|tl|bottom]
MIRROR_V x y NAME [args...] [ANCHOR center|tl|bottom]
MULTIPLY x y NAME [args...] [ANCHOR center|tl|bottom]
SYMMETRY_X x y centerX NAME [args...] [ANCHOR center|tl|bottom]

ANCHOR is a trailing option on a placement command, not a separate placement command. center (default) means visible-bounds center; tl means the local raster top-left; bottom means bottom-center. Example: STAMP 80 190 TOWER BRICK ANCHOR bottom. For older scripts, *_TL names remain supported as legacy top-left defaults; a trailing ANCHOR option overrides the default.

IMPORTANT ARGUMENT ORDER
Arguments ALWAYS come after the object name.
The color argument for a one-parameter macro goes at the end of the command:
STAMP 5 545 complex_step2 R
ROTATE 10 620 0 combined_over O
Do NOT write the color before the object name.
For multiple parameters, keep the same parameter order as the DEF declaration. Inside the DEF, use parameter names or explicit positional references such as $1 and $2; bare numeric values remain coordinates/literals.
Example:
DEF stripe c w h
  RECT 0 0 w h c
ENDDEF
STAMP 20 20 stripe Y 12 6

PLACEMENT ANCHOR RULE: all placement commands default to visible-bounds center. ANCHOR center keeps that behavior; ANCHOR tl places the object's local raster top-left at (x,y); ANCHOR bottom centers it horizontally and aligns its inclusive bottom row to y. ROTATE anchors the rotated result, while rotation itself is around the source object's center. Positive angles are clockwise. Transparent outer padding is ignored by center/bottom placement. If a raster has an even width or height, its center falls between pixels; use .5 coordinates when exact half-pixel centering matters.
Legacy migration: *_TL names remain supported as top-left defaults; a trailing ANCHOR mode overrides that default. Prefer the explicit trailing mode in new scripts.

6. RASTER MASKS
MASK result A MINUS B
MASK result A PLUS B
MASK result A OVER B
MASK result A AND B
# MINUS also accepts SUBTRACT or -; PLUS also accepts ADD or +

MASK creates a reusable raster recipe. A and B may be DEF objects or previous MASK results.
The four operations are intentionally different:
MINUS  = keep A where B is empty. B cuts holes out of A.
AND    = keep only pixels where both A and B are occupied. The result keeps A's color.
PLUS   = union of A and B. If both occupy the same pixel, A wins.
OVER   = layer B over A. If both occupy the same pixel, B wins.

This difference is important: PLUS and OVER are NOT the same operation.
Use different source colors when visually testing overlap ownership.

MASK coordinates use the original local coordinates of each source object. The two operands are NOT independently moved so that their bounding boxes start at the same local (0,0). This preserves meaningful positions such as a circle centered at (25,16) inside a 50x32 panel.

A MASK has no parameter list of its own. When a mask result is finally placed with STAMP, ROTATE, MIRROR_H, MIRROR_V, MULTIPLY, or SYMMETRY_X, the supplied argument list is forwarded independently to both source objects. Placement coordinates refer to the visible center of the resulting raster.
Example:
DEF base c
  RECT 0 0 40 30 c
ENDDEF
DEF hole
  CIRCLE 20 15 8 W
ENDDEF
MASK cut base MINUS hole
STAMP 29.5 64.5 cut R

For parameterized sources, the same argument positions are passed to both sides. Therefore source parameter layouts should normally be compatible.
Example:
DEF base c
  RECT 0 0 40 30 c
ENDDEF
DEF add c
  CIRCLE 20 15 8 c
ENDDEF
MASK union base PLUS add
STAMP 29.5 64.5 union G

To test PLUS versus OVER with visibly different overlap colors, prefer source DEFs with literal colors or otherwise make the operands produce different colors; a single final argument is forwarded to both parameterized sides.

7. REPETITION
LOOP variable start end step
  ...
ENDLOOP
The end value is inclusive. Positive step increases; negative step decreases.

NESTED LOOPS: use the exact same LOOP / ENDLOOP pair at every level. Each LOOP must have its own ENDLOOP. Do NOT use LOOPEND, END LOOP, or a different closing keyword for inner loops. Nesting is determined by block depth, not by different names for inner and outer loops. Example:
LOOP y 0 20 10
  LOOP x 0 20 10
    PIXEL x y WHITE
  ENDLOOP
ENDLOOP

8. CONDITIONS, BOOLEAN OPERATORS & TERNARY EXPRESSIONS
IF condition
  commands...
ELSE
  commands...
ENDIF

ELSE is optional. Every IF must have one ENDIF. IF blocks can be nested and can be used inside LOOPs and DEFs. Only the selected branch is executed. Conditions can contain spaces, parentheses, numeric expressions, and these operators:
- Comparisons: ==, !=, <, <=, >, >= (=== and !== are accepted aliases).
- Boolean: &&, ||, !; the word forms AND, OR, NOT are also accepted.
- Boolean literals: true and false (case-insensitive).
- Arithmetic: +, -, *, /, %; precedence follows normal programming-language order. Parentheses can make grouping explicit.
- Numeric values are true when nonzero and false when zero. Comparisons and boolean operations produce true/false.

Examples:
IF x % 2 == 0 && y >= 4
  PIXEL x y EVEN
ELSE
  PIXEL x y ODD
ENDIF

IF !(x < 3 || y == 0)
  CIRCLE x y 2 HIGHLIGHT
ENDIF

Ternary expressions use condition ? valueWhenTrue : valueWhenFalse. They are valid anywhere a single numeric or color argument is accepted. Keep command-argument expressions together as one token, usually by wrapping the full expression in parentheses. A color ternary returns the chosen color symbol or literal:
COLOR COLOR1 #ff4d6d
COLOR COLOR2 #488bff
DEF DOT c
  PIXEL 0 0 c
ENDDEF
LOOP x 0 9 1
  PIXEL x 5 (x%2==0?COLOR1:COLOR2)
  STAMP x 8 DOT (x%2==0?COLOR1:COLOR2)
ENDLOOP
RECT 0 0 (WIDTH>32?8:4) 2 COLOR1

Ternaries can be nested, but prefer parentheses when nesting to keep them readable. Color symbols such as COLOR1 and COLOR2 are values in a ternary branch, not arithmetic variables. Conditions inside DEFs can use DEF parameters and LOOP variables after substitution. FILL and all drawing operations affect the raster at the point where the command executes, so their results can differ depending on IF branch and command order.

9. COMMENTS
Full-line comments begin with #. Inline comments are allowed after whitespace. Hex colors beginning with # remain valid color literals.

10. ARTWORK STRATEGY
- Draw back-to-front: background, sky, distant forms, midground, foreground, details, highlights.
- Prefer strong silhouettes and a few meaningful shapes over huge numbers of individual PIXEL commands.
- Every large RECT must have a clear semantic purpose (building, ground band, water, road, wall, etc.). Never scatter rectangular filler into the sky or empty space.
- Do not place a full-width RECT over already finished mountains, clouds, buildings, or foreground forms unless it is intentionally a foreground/background band. Draw large background bands before the objects they should sit behind.
- Keep the sky visually open unless the requested scene specifically calls for clouds, architecture, birds, wires, or similar elements.
- Use GRADRECT for large sky, water, glow, and lighting transitions. Gradients interpolate alpha safely, including transparent endpoints.
- Use DITHERRECT for controlled texture, ramps, smoke, foliage, and subtle pixel transitions. Choose its pattern and coverage deliberately: at 0.5, BAYER2/4/8, FLOYD, JARVIS, and SIERRALITE currently look like checkerboards; ATKINSON at 0.5 tends toward larger square-like clusters. Other combinations may differ and have not all been tested. For richer texture, experiment with coverage around 0.3–0.4 or 0.6–0.7 and select what looks best. You may freely experiment with any supported pattern and coverage; do not use 0.5 by default if a checkerboard would be undesirable.
- Use RECT for masses, BOX for outlines, LINE for beams/roads/diagonals, CIRCLE/ELLIPSE for rounded forms, CIRCLEOUT/ELLIPSEOUT for the outline of circle and ellipse, and TRIANGLE for roofs, mountains, wings, fins, arrows, sails, shards, trees, cones, and other pointed forms.
- TRIANGLE uses three arbitrary vertices, not angles or side lengths.
- Use DEF + STAMP when a structure repeats. STAMP coordinates default to the visible center; use ANCHOR bottom to align feet/bases on a shared ground row, or ANCHOR tl for intentional top-left placement.
- Establish shared baselines with ANCHOR ground 190 and BASE AT ground; use BAR x BASE w h color for bottom-anchored filled structures.
- Default to a clear front/side view for architecture: the ground line is horizontal and buildings share a base y. Use top-down only when the scene calls for a map/overhead view. Perspective is a composition convention, not an automatic rendering transform.
- Use RAND/PICK for deterministic variation instead of complicated ternaries when choosing among several palette colors or sizes. Keep COLORDEF for the named palette; LET holds per-building computed values.
- Use BBOX temporarily to inspect an object's visible size/placement, then remove debugging boxes from final artwork.
- Compose complex DEFs from smaller DEF/MASK objects with STAMP, ROTATE, MIRROR_H/V, MULTIPLY, and SYMMETRY_X; each nested placement uses the same visible-center anchor.
- Use FILL only after drawing the boundaries that should contain it; its result depends on all pixels already drawn at that exact point in the script.
- Use MASK for cutouts, unions, intersections, and reusable composites.
- Use ROTATE for lean, tilt, fan, radial, or directional variation.
- Use LOOP + expressions for procedural spacing, repeated motifs, waves, stripes, and offsets.
- Draw the composition from top to bottom when constructing a test sheet. Keep test groups in separate rows with generous spacing so unrelated results cannot overlap accidentally.
- When testing a feature, isolate that feature first: source A, source B, A OP B, then place the result. Only after it is visually correct should you combine it with ROTATE/MIRROR/LOOP or other masks.
- Keep coordinates inside the intended composition and leave enough room around test objects.
- Drawing uses normal source-over alpha compositing: opaque colors replace the existing pixel, while #RRGGBBAA/rgba() colors blend over what is already there. Multiple translucent layers accumulate naturally.
- A fully transparent color (#00000000 or rgba(...,0)) has no visible effect.
- MASK operations are alpha-aware: MINUS subtracts right-side alpha, AND keeps the left color with intersected alpha, PLUS keeps A's visible color while preserving union coverage, and OVER performs normal B-over-A compositing.
- MULTIPLY uses a multiply blend for the placed raster while still respecting source alpha.
- MASK operations work on raster data and do not directly alter the canvas until the resulting object is stamped/rotated/mirrored.
- Do not invent unsupported commands or implicit variables.

MASK TEST CHECKLIST
For MINUS: use a solid rectangle and a centered circle; expect a clean hole.
For AND: use partially overlapping shapes; expect only their overlap.
For PLUS: use two overlapping shapes with different colors; expect the A color on the overlap.
For OVER: use the same setup; expect the B color on the overlap.
Then test STAMP, ROTATE, and MIRROR on the resulting object.

COMPOSITION SANITY CHECK
Before finishing, scan for accidental filler: large rectangles floating in the sky, full-width bands drawn after foreground objects, repeated structures with no semantic role, or shapes that exist only because RECT was convenient. Replace them with an intentional primitive or remove them.

OUTPUT CHECK
Before finishing, mentally verify:
GRID exists; colors are defined or valid literals; every DEF has ENDDEF; every LOOP has exactly one matching ENDLOOP (including nested loops, closed from inner to outer; never write LOOPEND); every IF has ENDIF with an optional ELSE; use non-reserved, single-token names for colors/variables/DEFs and never use BG as a palette symbol; boolean comparisons and ternary expressions are parenthesized where useful; every STAMP/ROTATE/MIRROR/SYMMETRY/MULTIPLY (or *_TL legacy variant) names an existing object; every MASK references existing objects; FILL occurs after the boundary or region it is meant to fill; numeric expressions use only supported values including WIDTH/HEIGHT; every object argument appears AFTER the object name; colors are not used as arithmetic; and no unsupported commands are invented.
