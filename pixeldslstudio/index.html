PixelDSL Language Reference

PixelDSL uses lowercase calls, reusable obj definitions, value-returning fn functions, brace-delimited blocks, composable transforms, and geometry-aware anchors. All primitives render into the same pixel-art engine.

Canvas and background

The canvas origin is top-left; positive y goes down. Dimensions are pixels. Use transparent alpha when desired.

grid(128, 128) bg(#00000000)
Palette and color values

Use a palette block or assign named colors directly. Colors support #RGB, #RGBA, #RRGGBB, #RRGGBBAA, rgb(), rgba(), and transparent.

colors { K #2e1140 H #c9a3f5 W #ffffff } red = #ff0000
Shapes: obj

An obj is reusable geometry in local coordinates. Parameters are passed by position. An obj can draw another non-recursive obj inside itself; nested pixels are composed at those local coordinates and contribute to its visible bounds. Object and function names must be unique.

obj car(c) { rect(0, 0, 30, 11, c) circle(8, 13, 3, K) } draw car(red) at (45, 216)
Small object and function forms

A fn always produces a value. Use explicit return expression in every branch, or implicit branch expressions. An implicit conditional may include an else, or omit it when a later final expression supplies the fallback for unmatched conditions. Branches may also assign a shared result variable, initialized beforehand when it needs a default, then read that variable as the final expression.

fn height(i) => 20 + rand(i, 5) * 40 fn grass_color() => #3b7a57 fn explicitColor(n) { if n >= 10 { return IN } elif n >= 9 { return C1 } else { return C9 } } fn implicitColor(n) { if n >= 10 { IN } else if n >= 9 { C1 } C9 } fn assignedColor(n) { result = C9 if n >= 10 { result = IN } elif n >= 9 { result = C1 } result }
Drawing, canvas anchors, and source anchors

draw uses the object's visible-bounds center by default. The trailing anchor name selects the new object's source point; use it for ordinary coordinate placement. A source modifier such as beard.top() selects the new object's source point when attaching it to a handle anchor. Canvas targets such as grid.bottom() select a point on the canvas. The trailing anchor clause takes precedence if both source forms are present.

draw tree at (22, 194) anchor bottom draw car at grid.bottom(0, -4) anchor top draw icon at grid.tl(12, 12) draw car at local
Attaching objects and offsets

Save a draw result to create a handle, then target one of its anchors to attach another object. The target anchor's offsets move the target point; the modifier after the new object selects its source anchor and offsets that source point. The two points are aligned. Offsets are pixels; negative y means up. By default, anchors use the complete visible raster bounds after transforms, not the exact silhouette. Inside an obj, frame(handle) optionally chooses a previously created child handle as the containing object's alignment frame. It changes the containing object's anchors, not its rendered bounds or pixels. Primitive calls can also be assigned to handles; their .x/.y values are the primitive's logical reference coordinate, while .c, .tl, and the other anchors use its raster bounds. Pixel and fill handles are single-point handles.

h = draw head at (64, 56) draw beard.top() at h.bottom(0, -8) draw beard.top(0, -1) at h.bottom(0, -8) draw ear at h.left(-2, 0) px = h.c.x py = h.c().y rect(px - 1, py - 1, 3, 2, GOLD) ci = rect(8, 4, 12, 8, WHITE) rect(ci.c.x - 1, ci.c.y - 1, 3, 2, GOLD)

An anchor is a coordinate point. Pass it where an (x, y) pair is expected, or read one scalar component with handle.c.x, handle.c.y, handle.tl.x, and so on. Both handle.c.x and handle.c().x are accepted. For point-valued anchors, bare and call forms are equivalent: grid.center, grid.center(), handle.top, and handle.top(). Optional offsets use the call form, for example handle.top(2,-1); a single offset means dx. handle.x/handle.y remain the handle's logical reference coordinate. On circles, .r is radius; use .right for the right anchor.

Four related but separate uses: draw car at p anchor bottom chooses the new car's source point; p.bottom() reads a point from an existing handle; anchor(ground, x, y) defines a reusable named coordinate; and place(x, y, h, tl) chooses which point of an existing handle is moved to the requested position.

place(point, handle[, anchor]) or place(x, y, handle[, anchor]) creates a virtual handle without drawing pixels. It preserves the original handle's size, anchors, and drawable raster (when it has one), moving the chosen anchor (default center) to the requested coordinate. Use place to reposition an existing handle; use instance to create a drawable object handle without drawing it first.

p = place(10, 0, h, tl) draw cloud at p.top(0, -7) rect(p.c.x - 1, p.c.y - 1, 3, 2, RED)
Instances (non-drawing object handles)

Use instance or its alias ins to rasterize an object and save its bounds, anchors, and pixels without drawing it. It must be assigned to a variable. The handle works anywhere a drawing handle or anchor is accepted. draw handle later composites its saved pixels at the stored position; an optional transform affects only that draw and does not mutate the saved instance. A draw result assigned to a variable is also drawable this way. Primitive handles have anchors but do not contain a saved object raster.

carRef = instance car(RED) at local triangle(carRef.left(-12, 7), carRef.left(-12, -3), carRef.left(3, 2), GOLD) draw carRef mirror = place(60, 25, carRef, center) draw mirror with trans flip x saved = draw car(BLUE) at (20, 25) draw saved with trans rot 15 draw car(GOLD) at carRef.top anchor bottom
Editable instance parts

Named assignments inside an obj become addressable after creating an instance. Edit nested primitive properties through the part path. Replacing a part with a primitive or nested object draw discards its previous subtree; later reads and draws rebuild the instance. fill and helper operations are not editable parts.

obj wheel(c) { tire = circleout(8, 13, 5, DARK) hub = circle(8, 13, 3, c) } obj car(c) { body = rect(2, 4, 30, 11, c) front = draw wheel(c) at (8, 13) } a = ins car(RED) at local a.body.color = BLUE a.front.hub.r = 4 a.front.hub.xy = (10, 14) a.front.hub.color = WHITE draw a

Primitives expose .xy, .x, .y, .color, and read-only .kind; shape-specific properties include .w/.h, .r, .rx/.ry, .p1… and .x1….yN. Gradient and dither .color aliases .color1. For circles, use .right for the right anchor because .r is radius.

Object alignment frame

frame(handle) is an optional statement inside an obj. It selects the bounds of an earlier primitive, draw, or instance handle as the containing object's anchor frame. Geometry outside that frame still renders and still contributes to the object's visible raster bounds. If omitted, anchors keep using the full visible bounds as before. A nested handle's own frame is inherited when selected.

obj carWithLamp(c) { carRef = ins car(c) at local triangle(carRef.left(-13,7), carRef.left(-13,-4), carRef.left(2,1), GLOW) draw carRef frame(carRef) } draw carWithLamp(RED) at (64,32)
Transforms

Transforms are applied to the object before placement. rot is clockwise degrees, scale accepts one or two values, and composition is left-to-right. flip x mirrors left↔right; flip y mirrors up↔down; flip may also take a parenthesized expression that resolves to x or y. The standalone stamp(x,y,obj) helper draws an object centered at the given point. mirror_h mirrors left↔right around a vertical line through x; mirror_v mirrors up↔down around a horizontal line through y. Standalone stamp/mirror_h/mirror_v/rotate/multiply/symmetry_x helpers accept obj shapes, never primitives, and are called directly (never as draw mirror_h(...)). Scaling uses nearest-neighbor sampling. multiply is a raster blend mode: RGB uses per-channel multiplication with source-over alpha weighting.

pose = trans rot 25 scale 1.2 draw tent(M) at (64, 99) with pose stamp(100, 60, tree) mirror_h(100, 60, tree) rotate(120, 90, -12, tree)
Primitive calls

All geometry primitives use comma-separated function calls.

pixel(x, y, c) fill(x, y, c) rect(x, y, w, h, c) box(x, y, w, h, c) # outline rectangle orect(x, y, w, h, c) # alias for box line(x1, y1, x2, y2, c) circle(x, y, r, c) ellipse(x, y, rx, ry, c) triangle(x1, y1, x2, y2, x3, y3, c) triangleout(x1, y1, x2, y2, x3, y3, c) otriangle(x1, y1, x2, y2, x3, y3, c) # alias poly(x1, y1, x2, y2, x3, y3, ..., c) polyout(x1, y1, x2, y2, x3, y3, ..., c) opoly(x1, y1, x2, y2, x3, y3, ..., c) # alias
Additional primitive tools

Circle/ellipse outlines, base-aligned bars, gradients, and ordered/error-diffusion dithering are supported. gradrect requires an explicit H or V direction. ditherrect requires both an explicit pattern and coverage (0–1); neither primitive has default arguments. poly/polyout accept 3–64 vertices as x,y pairs followed by a color. poly fills concave and self-intersecting shapes with even-odd filling; polyout draws a closed outline. Each primitive writes each covered pixel only once, including translucent colors.

circleout(x, y, r, c) ocircle(x, y, r, c) # alias for circleout ellipseout(x, y, rx, ry, c) bar(x, base, w, h, c) gradrect(x, y, w, h, c1, c2, V) ditherrect(x, y, w, h, c1, c2, BAYER4, 0.35)

Dither patterns: CHECKER, BAYER2/4/8, CLUSTER, DIAGONAL, HORIZONTAL, VERTICAL, ATKINSON, FLOYD (alias FLOYDSTEINBERG), JARVIS, STUCKI, SIERRA, SIERRALITE.

Inline sprites

sprite(x, y, scaleX, scaleY) draws a small comma-separated character map at its top-left origin. Each non-dot symbol names a palette color; . is transparent. The map's row and column counts determine its dimensions. It works at top level or inside an obj and expands to ordinary filled pixel cells.

sprite(100, 50, 2, 2) [ ., R, ., R, . R, R, R, R, R R, R, W, R, R ., R, R, R, . ., ., R, ., . ] sprite(150, 50, 1, 1) [ ., Y, ., Y, . ] obj badge(c) { sprite(0, 0, 1, 1) [ ., c, . c, c, c ] }
Variables and expressions

Assignments create or update values without let. Numeric expressions support +, -, *, /, %, comparisons, booleans, parentheses, and ternaries. WIDTH and HEIGHT refer to canvas dimensions; PI and E are constants. Math functions include abs, floor, ceil, trunc, round, sign, sqrt, pow, exp, log/log10, ln, log2, sin, cos, tan, asin, acos, atan, atan2, min, max, hypot, clamp, lerp, fract, deg, and rad. Trigonometric functions use radians.

x = i * 19 h = 20 + rand(i, 5) * 40 c = i % 2 == 0 ? RED : BLUE rect(x, 182 - h, 17, h, c)
Functions, conditionals, and loops

Blocks use braces, not indentation, and may be compact or multiline. else is optional; else if and elif are supported. Ranges use an exclusive end with .. and an inclusive end with ..=. Optional steps may be positive or negative, but cannot be zero. while repeats while its condition is true; update a variable inside the body and respect the execution safety limit.

fn tower_height(i) { 20 + rand(i, 5) * 40 } for i in 0..17 { if i % 2 == 0 { pixel(i, 4, RED) } else { pixel(i, 5, BLUE) } }
Deterministic randomness

rand(index, seed) returns a stable value in [0,1), repeatable for the same pair. pick(random, value1, weight1, ...) selects using positive weights; pick(random, value1, value2, ...) selects uniformly when the alternatives are nonnumeric values such as color names.

window = pick(rand(i, 42), WIN, 6, WINP, 3, K, 1) rect(x, y, 5, 8, window)
Masks and compositing

mask creates a named raster composite. Operations: MINUS/SUBTRACT, AND, PLUS/ADD, and OVER. multiply places an object using multiply blending; symmetry_x mirrors it around centerX.

mask(clipped, solid, MINUS, hole) draw clipped at (32, 32) multiply(12, 8, light, O) symmetry_x(32, 32, 64, gem)
Bounds and coordinate helpers

bbox draws an object's visible raster bounds for debugging. anchor(name, value) stores a reusable scalar or point; anchor(name, x, y) stores an explicit coordinate pair. base_at(value) assigns BASE, and base_at(x, y) assigns BASE as a point whose components are available through BASE.x and BASE.y. Use a scalar BASE for bar baselines; bar's base is the inclusive bottom row.

anchor(ground, 190) anchor(marker, 24, 40) base_at(ground) bar(40, BASE, 16, 48, STONE) base_at(24, 190) pixel(BASE, WHITE) bbox(64, 64, car, #00ffff)
Comments and draw order

Use # or // for comments. Hex colors remain intact; inline comments start after whitespace before a comment marker. Draw back-to-front because later objects appear above earlier ones.

bg(#0f172a) # night sky rect(0, 90, WIDTH, 38, ROAD) draw car(RED) at (48, 112)

CANVAS AND COLORS
Start with grid(width, height), then declare the palette, then set the background: grid(...), colors { ... }, bg(color). In a multiline colors block, write one `NAME #hex` (or `NAME = #hex`) entry per line. In a compact one-line colors block, use semicolon-separated assignments such as `colors { RED = #f00; BLUE = #00f }`; do not put several bare `NAME #hex` entries on one line. Do not call bg() with a named color before that color has been declared. Every named color must be declared before its first use anywhere, including bg(), primitives, object arguments, and sprite cells. Color names are case-sensitive and are never created automatically. Never invent a color name or assume a letter such as C, W, G, R, or B has a built-in meaning: each must be explicitly defined first. Ordinary variables must also be assigned before they are read; never use a variable or color name speculatively and declare it later. Do not rely on forward references for values. Coordinates start at the top-left; +y points down. Pixels outside the canvas are clipped. Supported color values: #RGB, #RGBA, #RRGGBB, #RRGGBBAA, rgb(), rgba(), transparent. Floating-point coordinates, radii, widths, and heights passed to primitives are rounded to the nearest integer before rasterization (half values round toward positive infinity). Sprite cells must be exactly . or a named palette color. Do not use BG as a color name or put arithmetic inside color literals.

OBJECTS AND FUNCTIONS
Define drawable geometry with obj name(params) { statements }. Primitive coordinates are local to the object. To draw another object inside an object, use `draw other(args...) at (localX,localY)`; its pixels become part of the parent at those local coordinates, contribute to its bounds, and transform with it. Never call an object as a bare expression (`other(...)` does not draw), and never write `draw rect(...)`: call primitives such as `rect(...)` directly. A new object draw always needs `at` placement. For a zero-parameter object, both `draw tree at (x,y)` and `draw tree() at (x,y)` are valid and equivalent. If an object has parameters, pass them in parentheses: `draw tree(size, color) at (x,y)`. Parentheses after an object name contain its parameters, NEVER its placement coordinates; `draw tree(40,180)` is not a placement. To create the same object without drawing it, assign an instance: `treeRef = instance tree(args...) at (x,y)`; `ins` is an exact alias for `instance`. Instances are drawable handles, not drawing commands. Replay one with `draw treeRef` or `draw treeRef with trans flip x`; replaying does not change the saved instance. Inside an `obj`, `frame(handle)` optionally selects a previously created primitive, draw, or instance handle as that containing object's alignment frame. Put it after the handle has been created. It changes the containing object's default center/top/bottom/left/right anchors, but does not crop, move, or hide geometry; everything still renders and still contributes to visible raster bounds. A selected nested handle's own alignment frame is inherited. Without `frame(...)`, the existing full-visible-bounds anchor behavior is unchanged. `draw` without `at` is only for an existing instance or a saved object draw result, never for an object name. A saved draw result is written `treeRef = draw tree(args...) at (x,y)`. Do not define the same obj or fn name twice: duplicate definitions are errors. Definitions may appear in any order relative to other definitions; they do not draw anything. Only drawing commands determine visual layer, in source order. Compact form is `obj name(params) => statement; statement;`. Define value functions with `fn name(params) { assignments; final_expression }` or `fn name(params) => expression`. The last expression is returned; `return expression` is also accepted. Functions may use `if`/`else if`/`else` to choose a value; every branch must produce a value or assign the same result variable, which can then be the final expression. Functions compute values; use obj for drawable geometry. Assignments need no let: `x = expression`. A value-producing conditional may use implicit branch expressions with an else branch, or omit else when a later final expression supplies the fallback for unmatched conditions: `fn color(n) { if n >= 10 { IN } else if n >= 9 { C1 } C9 }` returns IN at n >= 10, C1 at n >= 9, and C9 otherwise. For assignment branches, initialize a shared result variable before the conditional when it needs a default, assign it in branches, then use it as the final expression. Keep explicit-return and implicit-value styles separate within a conditional chain. Every obj or fn name must have exactly one definition.

EDITABLE INSTANCE PARTS
Inside an obj, a named assignment creates an addressable part. Unassigned drawing commands remain ordinary geometry. Create an instance with `carA = ins car(RED) at local`, then edit named paths such as `carA.body.color = BLUE`, `carA.front.hub.r = 4`, and `carA.front.hub.xy = (10,14)`. Read them back with expressions such as `p = carA.front.hub.xy` or `r = carA.front.hub.r`. Rebuild happens before a later draw or bounds-dependent read; edits do not retroactively change pixels already drawn.
All primitive parts expose `.xy`, `.x`, `.y`, `.color`, and read-only `.kind`. Rectangular forms (`rect`, `box`, `bar`, `gradrect`, `ditherrect`) expose `.w` and `.h` as applicable. `gradrect` also exposes `.color1`, `.color2`, `.direction`; `ditherrect` exposes `.color1`, `.color2`, `.pattern`, `.coverage`. Circles expose `.r`; ellipses expose `.rx` and `.ry`; lines expose `.p1`, `.p2`, `.x1`…`.y2`; triangles expose `.p1`…`.p3` and coordinate components; polygons expose `.p1`…`.pN` and coordinate components. `.color` on gradients/dither aliases `.color1`. Drawable parts expose read-only bounds anchors such as `.center`, `.left`, `.right`, `.top`, `.bottom`, `.tl`, `.tr`, `.bl`, `.br`. On circles `.r` means radius, so use `.right` for the right anchor.
A part may be replaced with a primitive call or a nested `draw` statement; replacement discards the previous nested subtree. Both replacement directions are supported (primitive-to-object and object-to-primitive). A later property edit may target the replacement's new child parts. Invalidated children and unsupported shape properties must produce errors. `fill`, raw sprite blocks, and helper operations such as `stamp`, `rotate`, `mirror_*`, `multiply`, and `symmetry_x` are not addressable parts. Repeated creation of the same named part in one object execution is an error; dynamic part arrays are not supported.

SPRITES
Use the exact call form sprite(x, y, scaleX, scaleY) [ on its own line, then one row per line, then ] on its own line; a one-row sprite may put its row and closing ] on the same line. The parentheses and all four arguments are required. Separate cells with commas. Each cell must be either . (transparent) or the exact name of a color already defined in the palette. Sprite letters are NOT colors by themselves: if a sprite uses C, W, and G, define C, W, and G first. Do not use undefined symbols as shorthand for guessed colors. The number of columns and rows defines sprite dimensions; scaleX and scaleY are the size of each map cell in pixels, not row/column counts. Sprites work at top level and inside obj bodies, using the same local coordinates and composition rules as other primitives. Example:
colors {
  C #604080
  W #d8d8e8
  G #70b890
}
obj observatory_window() {
  sprite(-4, -5, 1, 1) [
    ., C, C, C, .
    C, W, W, W, C
    C, W, G, W, C
    C, W, W, W, C
    ., C, C, C, .
  ]
}

PRIMITIVES
Use lowercase calls with comma-separated arguments: pixel(x,y,c), fill(x,y,c), rect(x,y,w,h,c), bar(x,base,w,h,c), box(x,y,w,h,c), orect(x,y,w,h,c), line(x1,y1,x2,y2,c), circle(x,y,r,c), circleout(x,y,r,c), ocircle(x,y,r,c), ellipse(x,y,rx,ry,c), ellipseout(x,y,rx,ry,c), triangle(x1,y1,x2,y2,x3,y3,c), triangleout(x1,y1,x2,y2,x3,y3,c), otriangle(x1,y1,x2,y2,x3,y3,c), poly(x1,y1,x2,y2,x3,y3,...,c), polyout(x1,y1,x2,y2,x3,y3,...,c), opoly(x1,y1,x2,y2,x3,y3,...,c), gradrect(x,y,w,h,c1,c2,H|V), ditherrect(x,y,w,h,c1,c2,pattern,coverage), bbox(x,y,obj(args...),outlineColor). `gradrect` requires exactly 7 arguments and an explicit H or V direction; there is no default. `ditherrect` requires exactly 8 arguments, including both pattern and coverage; there are no defaults. `bbox`'s fourth argument is an outline color value, not a boolean. Aliases: orect = box, ocircle = circleout, otriangle = triangleout, opoly = polyout. Outline-only forms are box/orect, circleout/ocircle, ellipseout, triangleout/otriangle, and polyout/opoly; they do not fill the interior. poly/polyout require 3 to 64 vertices, written as x,y coordinate pairs followed by exactly one final color argument (7 to 129 total arguments; always an odd count). poly fills using the even-odd rule and supports concave/self-intersecting outlines; polyout draws only the closed boundary. triangle takes exactly three explicit vertices and one color (7 arguments); triangleout/otriangle draw its closed outline. Every primitive must cover/write each pixel at most once per call: do not triangulate a polygon into overlapping pieces and do not redraw shared vertices/edges with translucent colors. Later independent drawing calls still blend in normal draw order. BBOX outlines visible raster bounds for debugging.

PLACEMENT AND DRAW ORDER PRIORITY
Definitions (obj and fn) do not produce pixels. They only define reusable geometry or values. Defining an object before or after another definition does not determine its visual depth. Drawing commands render immediately in source order; later drawing commands appear over earlier ones. Compose every scene back-to-front: draw the background and distant scenery first, then midground, foreground, details, and highlights. Never draw a background or large terrain shape after foreground objects if it would cover them.

Preferred object placement syntax:
draw object(args...) at (x,y) anchor bottom
The trailing `anchor name` clause selects the new object's source anchor. Use this form when choosing a source anchor for ordinary coordinate placement. Do not substitute `.bottom()` or another source-anchor modifier for the trailing clause in that situation. This restriction is only about choosing the new object's source anchor: `grid.top()` and `handle.bottom()` are also coordinate point values and may be passed to primitives or other coordinate-taking calls. Source-anchor modifiers are supported when selecting a source point on a newly drawn object while attaching it to a handle.

`at local` is a special placement mode, not a coordinate or anchor. It maps the object's original local origin (0,0) to the current drawing origin; at top level that is the canvas origin, and inside an obj it is the parent object's local origin. It does not center, anchor, or translate the object; negative local coordinates extend off-origin. Do not combine `at local` with `anchor name`, canvas anchors, handles, or ordinary coordinate placement.

For ordinary placement, draw object(args...) at (x,y) aligns the object's visible-bounds center to the target point unless a source anchor is specified. Supported source anchors: center/c, top/t, bottom/b, left/l, right/r, tl, tr, bl, br, top_left, top_right, bottom_left, bottom_right.

Canvas anchors are placement targets and coordinate points, using pixel coordinates: grid.top, grid.bottom, grid.left, grid.right, grid.tl, grid.tr, grid.bl, grid.br, and grid.center. Both the bare form (`grid.center`) and call form (`grid.center()`) resolve to the same point; call form accepts optional pixel offsets (`grid.center(dx,dy)`). Handle anchors work the same way: `h.top`, `h.top()`, and `h.top(dx,dy)` are valid. One offset means dx with dy defaulting to zero. This shorthand applies when reading an anchor point; it does not replace the trailing `anchor bottom` clause, which chooses the source anchor of the newly drawn object. Canvas anchor coordinates refer to pixels 0..WIDTH-1 and 0..HEIGHT-1, so offsets can intentionally place pixels off-canvas. Target offsets move the target point. Source-modifier offsets, e.g. `h.top(dx,dy)`, offset the chosen point relative to the handle's bounds; the renderer aligns that point to the target. Offsets are in pixels; negative y means up. For circles, `.r` is the radius; use `.right` for the right-side anchor.
Coordinate anchors are also point values anywhere a primitive or coordinate-taking helper expects an (x,y) pair. Examples: `pixel(grid.top(), WHITE)`, `circle(grid.bottom(0,-2), 3, GOLD)`, `ggg = draw diamond at (140,35)` followed by `circle(ggg.bottom(),2,WHITE)`. You may store a point in a variable (`p = grid.center()`) and pass it as the first coordinate argument (`pixel(p, WHITE)`, `circle(p, 3, GOLD)`). Anchor offsets are optional; `grid.b`, `grid.bottom`, `ggg.bottom`, and `ggg.bottom()` all mean zero offsets. Use the same point syntax for line endpoints and polygon vertices. A point is a pair of coordinates, not a color or scalar.

Point values are ordinary two-coordinate values. They can be stored, passed to `fn` and `obj` parameters, returned from functions, and used wherever a coordinate pair is accepted. Examples:
`fn move(p,dx,dy) => (p.x + dx, p.y + dy)`
`q = move(grid.c, 2, -1)`
`pixel(q, WHITE)`
`fn identity(p) => p`
`p = identity(grid.tl)`
`obj marker(p) { pixel(p, WHITE) }`
`draw marker((3,4)) at local`
A point passed into an object parameter is interpreted in that object's local coordinate space. A point does not retain a world/local transform; it is just an `(x,y)` pair. Use `grid.anchor` or `handle.anchor` directly inside an object when you need that anchor resolved in the object's current drawing context.

An assignment captures a placed drawable handle: `h = draw head at (64,56)`. To capture without drawing, use `h = instance head at (64,56)` (or `h = ins head at (64,56)`). An instance stores its raster, visible bounds, and anchors but does not composite pixels. Use `draw h` to composite it later at its stored position; `draw h with trans flip x` draws a transformed copy without modifying h. An assigned object draw result can also be replayed with `draw h`; assigned primitive handles are geometry-only and cannot be replayed. Attach another object by targeting an anchor on an already-created handle: `draw beard at h.bottom(0,-8) anchor top`. Here `anchor top` chooses the new beard's source point, while `h.bottom(0,-8)` chooses the target point eight pixels above the head's bottom anchor. Define or instance the parent before referencing its handle. Anchors use complete visible raster bounds after transforms by default, including nested objects and protruding details; an obj can opt into a child handle's bounds with frame(handle). Anchors do not describe the exact contour. When placing objects resting on the same surface, align their bottom anchors to the same ground baseline. Never assume an object's local origin is its visible center or bottom.
Keep the four anchor forms distinct: the trailing `anchor top` clause chooses the source point of the object being drawn; `h.bottom()` reads a coordinate from an existing handle; `anchor(ground, x, y)` declares a reusable named coordinate; and the optional fourth argument of `place(x,y,h,tl)` chooses which source point of h is repositioned. They are related concepts, not interchangeable syntax.
Primitive calls can also be assigned to variables and return drawing handles: `ci = circle(10,10,6,RED)`. The primitive is drawn immediately. `ci.x` and `ci.y` expose its logical reference coordinate (circle center, rectangle origin, line's first endpoint, etc.); `ci.c`, `ci.tl`, and other anchors refer to the primitive's visible raster bounds. Read an anchor component as a scalar with `h.c.x`, `h.c.y`, `h.tl.x`, and so on. Both `h.c.x` and `h.c().x` are accepted. `h.x` and `h.y` are not aliases for center coordinates. `pixel` and flood-fill `fill` handles are point handles anchored at their seed coordinate.

`place(point,handle[,anchor])` or `place(x,y,handle[,anchor])` creates a virtual handle without drawing pixels. It keeps the source handle's bounds, anchor behavior, and drawable raster when present, but repositions it so the chosen anchor (default `center`) is at `(x,y)`: `p = place(10,0,h)`. You can then use `p.x`, `p.y`, `p.top()`, `p.bottom()`, and component access such as `p.c.x` as coordinate values; if h is drawable, `draw p` draws that same raster at the new position. `place` repositions an existing handle; it does not create an object instance. A virtual handle can be created from a primitive handle, an instance, or an assigned draw handle, and can be used inside objects too.

Reusable transform variables: `pose = trans rot 25 scale 1.2 flip x`; apply the variable with `draw tent(M) at (64,99) with pose`. `pose` is an ordinary variable name, not a transform keyword. For an inline transform, write `draw tent at (55,185) anchor bottom with trans rot -5`. `rot` is clockwise degrees. `scale` accepts one or two factors. Composition is left-to-right: rotate first, then scale, then flip. `flip x` mirrors left↔right across a vertical axis; `flip y` mirrors up↔down across a horizontal axis. `flip` may also take a parenthesized expression that resolves to `x` or `y`, e.g. `flip (i % 2 == 0 ? x : y)`. The standalone `stamp(x,y,obj(args...))` draws an object centered at the point. The standalone `mirror_h(x,y,obj(args...))` mirrors left↔right about the vertical line through x; `mirror_v(x,y,obj(args...))` mirrors up↔down about the horizontal line through y. These helpers are commands, not objects: call `mirror_h(x,y,my_obj)` directly and never write `draw mirror_h(...)`. Their final argument must be a defined `obj` name or call, never a primitive such as `rect(...)`, `circle(...)`, or `triangle(...)`; wrap primitive geometry in an `obj` first. Also available: `rotate(x,y,angle,obj(args...))`, `multiply(x,y,obj(args...))`, and `symmetry_x(x,y,centerX,obj(args...))`. Shape helpers accept either spread arguments such as `mirror_h(100,60,tree,40)` or an inline object call such as `mirror_h(100,60,tree(40))`. Transformations operate on the placed raster. The `with transformName` (or inline `with trans ...`) clause and the `anchor name` clause may appear in either order. `multiply(x,y,obj(args...))` is a compositing/placement helper: RGB channels use per-channel multiply (`dst * src / 255`), while alpha uses standard source-over weighting. It is not a math multiplication function or a color primitive.

MASKS
A mask is a top-level declaration, not a drawing command; do not place mask() inside an obj body. ALWAYS write it as a function call with parentheses and exactly four comma-separated arguments: mask(resultName, sourceA, OP, sourceB). Never write a bare form such as `mask resultName, sourceA, OP, sourceB`. The first argument is the new mask name; sourceA and sourceB must be names of obj or mask shapes; OP must be MINUS, AND, PLUS, or OVER. Object and mask dependencies are registered before drawing, so a source may be defined later in the file; mask dependency cycles are errors. Example:
colors {
  CYAN #50d8e8
  VIOLET #9860d8
  GOLD #f0c050
}
obj sigil_disc() { circle(0, 0, 10, VIOLET) }
obj sigil_bar() { rect(-12, -3, 24, 6, GOLD) }
mask(sigil_intersection, sigil_disc, AND, sigil_bar)
draw sigil_intersection at (32, 32)
The same draw arguments are forwarded to both source shapes, so their parameter lists should be compatible. A mask preserves source objects' local coordinates and does not draw until placed. MINUS cuts B's alpha out of A (a transparent hole); AND keeps only overlap using A's color; PLUS unions both and A wins overlap; OVER composites B on top of A, so B's color appears in overlap. PLUS and OVER are not equivalent. For testing, give A and B visibly different colors and use a transparent background to distinguish a hole from a colored overlap. Never omit the parentheses.

CONTROL FLOW AND EXPRESSIONS
Blocks use balanced braces and may be multiline or compact on one line. Examples: `if cond { pixel(x,y,C) }`, `if cond { ... } else { ... }`, and `if a { ... } else if b { ... } elif c { ... } else { ... }`. The first true branch runs; later branches are skipped. `else` is optional for ordinary statement conditionals. `else if` and `elif` mean the same thing, and any number of branches may be chained. `for i in 0..10 { ... }` uses an exclusive end; use `..=` for an inclusive end. Optional step: `for i in 0..20 step 2 { ... }`. `while condition { ... }` repeats while its condition is true; update a variable inside the body so it eventually becomes false. Both loop types have safety limits. Steps may be positive or negative, but must be non-zero and move toward the range end (e.g. `for i in 10..0 step -1 { ... }`). Object bodies may contain `if`/`else`, `for`, `while`, and local assignments.

A `fn` must produce one value. It may return explicitly with `return expression`; this immediately exits the function, so put a return in every branch that should produce a value and do not add a trailing result expression. Or use an implicit final expression: assign the same result variable in the conditional branches, include an `else` so every path assigns it, then put that variable as the final expression after the conditional. These are two alternative styles; both are supported. A simple function may also consist of assignments followed by one final expression, or use the one-line `fn name(args) => expression` form. Nest braces correctly; separate multiple statements with semicolons when they share a line. Arithmetic: + - * / %. Comparisons: == != < <= > >=. Boolean: && || ! and and/or/not. Ternary: condition ? valueA : valueB. Use parentheses around compound expressions when needed. `WIDTH` and `HEIGHT` are numeric canvas dimensions. Constants: `PI` and `E` (case-insensitive). Math functions: `abs(x)`, `floor(x)`, `ceil(x)`, `trunc(x)`, `round(x)` (half values round toward positive infinity), `sign(x)`, `sqrt(x)`, `pow(x,y)`, `exp(x)`, `log(x)`/`log10(x)` (base 10), `ln(x)` (natural logarithm), `log2(x)`, `sin(x)`, `cos(x)`, `tan(x)`, `asin(x)`, `acos(x)`, `atan(x)`, `atan2(y,x)`, `min(a,...)`, `max(a,...)`, `hypot(a,...)`, `clamp(x,lo,hi)`, `lerp(a,b,t)`, `fract(x)`, `deg(x)` (radians to degrees), and `rad(x)` (degrees to radians). Trigonometric inputs and outputs use radians. `rand(index,seed)` is deterministic in [0,1); `pick(random,value1,weight1,...)` selects by positive weights, while `pick(random,value1,value2,...)` selects uniformly when the alternatives are nonnumeric values such as colors. `anchor(name,value)` stores a reusable scalar or point, and `anchor(name,x,y)` creates a point explicitly. `base_at(value)` sets BASE; `base_at(x,y)` stores a point whose components are `BASE.x` and `BASE.y`. Use a scalar BASE for `bar`, which uses an inclusive bottom-row coordinate.

DITHERING AND COLOR
Dither patterns: CHECKER, BAYER2, BAYER4, BAYER8, CLUSTER, DIAGONAL, HORIZONTAL, VERTICAL, ATKINSON, FLOYD (alias FLOYDSTEINBERG), JARVIS, STUCKI, SIERRA, SIERRALITE. Coverage ranges 0..1 and controls the approximate share of color2. At 0.5 several patterns render as checkerboards; try 0.3–0.4 or 0.6–0.7 for other textures. Alpha colors composite in draw order using source-over. `transparent` is alpha zero, so drawing it does not erase existing pixels; use masks when you need transparent cutouts. FILL is order-dependent: draw boundaries first; it fills the 4-connected matching region on the current raster.

ARTWORK RULES
Compose back-to-front: background, distant shapes, midground, foreground, details, highlights. Use a limited coherent palette, clear silhouettes, meaningful large shapes, and reusable objects. Prefer shapes and loops over many individual pixels. Keep the sky open unless the scene calls for clouds or structures. Do not place filler rectangles or cover finished foreground with later background bands. Use triangles for roofs, mountains, fins, shards, and other pointed silhouettes. Use deterministic randomness. Keep repeated structures aligned to intentional baselines. Remove debug bbox calls from final art.

FINAL CHECK
Output only the code block. Ensure every name exists, calls have correct argument order/count, all braces close, mask dependencies resolve without cycles (forward declarations are allowed), handle attachments and `frame(handle)` reference earlier handles, and every command is supported.
